# 素材理解索引工作流 v1.0

## 目标

让 Excel、PDF、Word、PPT、图片、视频等非 Markdown 原件被 Obsidian 和 AI 理解，同时保留原件不变。

本流程只生成或补齐 `来源保留本地` 的“资料理解模块”。它不是全文转换、不是医学结论提炼、不是自动分类和移动。

2026-08-26 用户已授权：每次用户明确要求“整理收件箱”“整理资料”“归档会议”“分类文件”等整理任务时，先执行本流程作为整理前置步骤。重点是为新进附件新建索引卡；既有附件卡只做必要查漏补缺“资料理解模块”。本流程仍不得移动、删除、重命名、覆盖原件或生成正式结论。

## 三层结构

1. 原件层：原文件保留在 `来源保留本地` 或待处理时保留在 `来源保留本地`。
2. 索引层：每个原件对应一张 `asset_*.md` 标签卡，链接原件并记录格式、路径、用途、字段和复核点。
3. 提炼层：只有在用户确认后，才从索引或原件进一步生成 SOP、会议纪要、医学资料、经营方法论或卡片盒笔记。

## 批量更新方式

先预览：

```powershell
.\8-素材库\工具脚本\生成素材理解索引.ps1
```

确认后执行：

```powershell
.\8-素材库\工具脚本\生成素材理解索引.ps1 -Apply
```

只为新文件建卡，不补旧卡：

```powershell
.\8-素材库\工具脚本\生成素材理解索引.ps1 -CreateNewOnly -Apply
```

只扫描收件箱：

```powershell
.\8-素材库\工具脚本\生成素材理解索引.ps1 -ScanRoots "0-收件箱" -Apply
```

## 整理前置入口

每次用户明确要求整理资料时，先运行：

```powershell
.\8-素材库\工具脚本\整理前更新素材理解索引.ps1
```

该入口会：

1. 调用 `生成素材理解索引.ps1 -Apply`。
2. 为新进附件创建 `asset_*.md` 索引卡。
3. 对既有索引卡仅做必要查漏补缺，避免重复追加。

## 触发边界

- 这不是定期任务、后台任务或自动采集；只在用户明确要求整理资料时作为前置步骤运行。
- 重点处理新进附件发卡；既有卡片只做查漏补缺。
- 脚本不移动、删除、重命名或覆盖原始附件。
- 脚本不读取完整正文，不做 OCR，不抽取患者信息。
- 脚本只根据路径、文件名和格式生成待复核索引；所有用途、口径、责任人、版本和结论都保留为 `TBD`。
- 医学资料未经过正式医学审阅前，不得作为诊疗结论或对外宣教依据。
- `0-收件箱` 中的新资料仍需按《文件归属指引》逐项建议分类并确认后再移动。
